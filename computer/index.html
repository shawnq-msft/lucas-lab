    为什么写错最后一行，两种方法的结果不同？

    在这个小实验里，编译器会先检查整份程序，所以最后一行不认识就不开始执行；解释器已经执行了前面的正确行，遇错才停止。试试两种方法，观察屏幕！

    这是教学模型，不是所有真实语言的完整实现。真实编译器还会做优化和生成机器码；解释器也可能先解析整份程序、编译成字节码或使用 JIT。Python 不是简单的“原文逐行直接执行”。上面翻译后的指令只是自定义记号，不是真实 CPU 机器码。

    输入 → 内存

    取指 → 译码 → 执行，究竟是什么意思？

    取指：按 PC（书签）从内存取一条指令放进 IR。译码：控制器读懂这条指令。执行：搬数字、计算、写回或显示。然后重复，直到 HALT 停机。

    五个基本部分是输入设备、输出设备、存储器、控制器和运算器。这里把后两者画在 CPU 内。彩色传送条代表总线（传消息的道路）；真实指令和数字都用二进制存储，我们用文字方便看懂。这里没有模拟缓存、流水线和操作系统，也不是硬件电路仿真。
