01 / DECIDE BEFORE BUILDING

先选问题，
再选比赛与工具。

一个毛豆能解释、能验证的小项目，比几份大而空的“AI产品方案”更值得做。

02 / SAME CORE, DIFFERENT PROOF

共同点：真实问题、原创贡献、过程证据。

这些是跨赛事准备的共同底座，不等于每场赛事逐条相同的强制规则。每场仍以正式模板和评审要求为准。

  1. 说清楚谁遇到什么问题。不要先堆“大模型＋机器人＋物联网”，再寻找用途。
  2. 让毛豆拥有核心决定。选题、采样、关键逻辑、测试、失败解释，应留下孩子自己的记录。
  3. 证明有效，也证明边界。展示失败案例、误判原因和不能使用的情况，不只拍一次成功。
  4. 留下可追溯版本。原始素材、数据来源、代码/提示词、人工修改、演示和贡献说明都保存。

04 / ONE SMALL, TESTABLE IDEA

毛豆选题：优先熟悉场景，而非最大技术量。

下列是备选方案，不是已实现作品或合规承诺。以毛豆愿意持续观察、能自己解释、能收集真实样本为第一关。现成工具能解决的问题，不必重新训练大模型。

优先候选 / 运动生活

网球挥拍练习记录器

最小版本：先限定单人、固定机位、离线短视频，辅助统计挥拍次数和训练时长；毛豆人工标注真实次数，对照程序输出。只谈训练记录，不评价“专业动作标准”，不提供医疗或康复建议。

AI的必要性：若用现成人体关键点模型，解释模型输出怎样进入计数逻辑；不是装上摄像头就有AI。先与手动按钮/简单阈值方案比较，说明它解决了什么。

验证：不同人／光线／角度的独立测试片段，展示漏计和误计；以人工计数为参照，明确训练调参素材与最终测试素材分开。计数误差、处理延迟和失败条件都记录。

赛事适配：智能未来·科技助健最贴题；WAICY可按实际能力选L3或L4；学校AI待规则；创客若要求实物，确认后再加小显示器，不为了“显得高级”先做机器人。

停手条件：若基本计数还不稳定，先完成小范围验证，不扩到多动作识别、在线多人和云端诊断。

兴趣更强时 / 地质采集

我的地质标本整理与相似检索

最小版本：自己的标本档案＋拍摄条件＋可检索标签，再考虑图片相似检索或有来源的问答。让AI提供线索，不把矿物名称当已确认结论。

关键区别：照片分类、相似检索、地质鉴定不是同一件事。颜色相近可能不同矿物，湿润、光照和背景也会误导。记录“不确定”，不要拍照后就推荐食用、触摸未知物或危险采样。

赛事适配：WAICY较宽的真实问题主题、创客前沿科技方向可讨论；学校AI待核。不适合直接投智能未来·科技助健，不要强行贴“健康”标签。

轻量备选 / 视觉表达

让同学看懂网球规则的AI海报

最小版本：毛豆先写给初学者的规则信息结构，再生成图像、人工排版和核查；至少保留三个有改进关系的版本，请同学复述海报表达的规则，找出误解后再改。

赛事适配：智能未来·智能艺术生成的海报方向明确匹配；学校生成作品赛待主题和媒介确认；WAICY视觉创作需另核材料与复用。它不是AI应用项目的替代品。

注意：文字、球拍握法、球场比例和动作姿态逐项核查；不要用AI图像捏造“真实比赛现场”。

太空运矿游戏还能用吗？

可以延续兴趣，但普通游戏、规则引擎和AI项目是不同类型。先问是否真的有需要AI解决的问题；加入生成素材或调用聊天接口，不自动构成AI创新应用。创客主题适配、学校AI要求都要核实；智能未来·科技助健不应勉强套用。

05 / CHOOSE THE SIMPLEST PLATFORM

平台怎么选：先可解释，再加能力。

这是工程建议，不是赛事指定或已获批准的平台列表。学校附件若限定平台，以规则为先。账号年龄、监护人许可、付费、联网及导出能力，都要实际核查。

根据任务选平台，不根据“AI”标签选平台
路线适合做什么优点与代价毛豆的选择
Python＋本地文件
按需加OpenCV／现成人体关键点模型		运动视频计数、数据整理与测试逻辑、数据可追溯；环境、模型许可及部署需处理。识别质量必须实测。应用项目优先尝试。先读录制视频，后开实时摄像头；不从训练大模型起步。
HTML／JavaScript
按需加浏览器模型		易分享的交互演示、标本档案、结果可视化分享方便；摄像头权限、浏览器兼容、模型加载与离线资源要测试。公开静态站不能藏API密钥。孩子能解释事件和状态逻辑才选；页面漂亮不能替代AI与测试证据。
Scratch／学校已有图形化平台交互逻辑、传感器演示搭建直观；AI扩展、设备和导出差异大，需试验，不假定都支持。若学校有教师和成熟套件优先复用；检查能否导出代码／工程及现场运行。
低代码智能体平台
如Dify、Coze类工具		带资料来源的问答、交互原型原型快；可能依赖云端、付费、账号，且容易变成通用聊天壳。检索来源和错误要可见。只在问题确实需要问答时选；年龄条款、服务可用性和作品导出先核。按实际能力对应WAICY等级。
ESP32／micro:bit等已有硬件传感器输入、显示与反馈动手证据充分；接线、电源、机械稳定和运输增加成本。普通阈值控制不是AI。软件验证后再加；家长负责工具安全，不替孩子完成全部接线与逻辑。
AIGC图像＋排版／剪辑工具运动海报、宣传视频适合创作赛；须保留提示词、版本、人工编辑、素材版权与事实核查。艺术线用，不拿来冒充应用开发或真实研究结果。

建议默认：运动应用先“Python＋录制视频＋人工标注＋结果表”；有稳定闭环再考虑网页展示或硬件。若孩子更愿意讲故事而非调程序，走海报创作线，不强迫包装成工程项目。

最低技术验收与隐私保护

  • 在实际参赛电脑上从头启动，检查网络、摄像头权限、资源路径和重启后状态。
  • 无网时能展示哪些功能，说清楚；保留本地演示视频和截图备份，不把录播假装实时运行。
  • API密钥不写进网页、Git仓库或答辩截图；云端接口由监护人妥善管理。
  • 不把人脸、同学姓名或原始训练视频上传到公开Pages；必要采集须征得本人及监护人同意。注意背景中的其他儿童。

06 / BUILD AN EVIDENCE TRAIL

从想法到答辩：先小，再真，再完整。

这是建议流程，不是官方课程或完成时间保证。每一步都留下毛豆的原始说明，避免最后由家长补造工程笔记。

  1. 定规则、定问题

    拿本校通知与完整附件，确认主题、名额、现场冲突和跨赛条款。孩子用自己的话写“谁、何时、遇到什么困难”。不先定设备清单。

  2. 做不用AI的基线

    用人工计数、纸质档案或简单按钮先解决一次。解释现有方法哪里不够，AI新增什么价值；不需要AI就坦诚说不需要。

  3. 只实现一个功能

    输入 → 处理 → 输出，画出流程图。选少量合法来源的数据先跑通，固定软件和模型版本。AI辅助写代码时保存对话，孩子逐段解释关键逻辑。

  4. 独立测试，留下失败

    先确定测什么、怎样判对错；开发样本与最终测试分开。记录样本数量、实际结果、漏计／误判、延迟、限制。没有跑过的结果不能写成准确率。

  5. 按赛事分别装配材料

    共用素材库保存需求、原始数据、版本、测试、授权与贡献清单；再分别制作各赛模板。创客区赛≤3分钟匿名视频，智能未来应用已实现时1—5分钟，不能混用时长。

  6. 让毛豆自己演示与改动

    不背家长稿。能现场解释一条错误、修改一个小参数并预测结果；创客市级还有“动手做”，不是只展示成品。

三方分工：帮助可见，贡献不冒领

毛豆负责

选题与需求、采样/标注、核心逻辑理解、测试记录、版本取舍、演示问答。能解释哪些不是自己写的。

家长负责

报名与规则核对、采购、安全、账号/费用、安装环境和适度提示。把帮助写进日志，不代做整套系统或编造研究过程。

AI可以辅助

查概念、解释报错、提供备选实现、生成可修改素材。不能代替孩子做关键判断，不生成虚假测试数据；各赛许可与披露要求不同。

答辩前，毛豆能否回答这六个问题？
  1. 你自己遇到的问题是什么？为什么选它？
  2. 不用AI能做到什么？为什么还用AI？
  3. 数据从哪里来？有没有测试没见过的样本？
  4. 最差的一次结果是什么？你怎么修改？
  5. 哪些是你、家长、同伴、AI分别做的？
  6. 现场没有网络／模型误判时怎么办？
