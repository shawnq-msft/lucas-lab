01 / NETWORK★ 入门
浏览器→DNS→服务器

Protocol Explorer

一条请求的旅行

网页不是“突然出现”的。沿着数据包时间线，看看名字如何变成地址、连接如何建立、内容如何送达。

探索内容：HTTP · DNS · TCP · 数据包时间线

先会什么 会打开网页；知道浏览器与网站不是同一回事。

动手做
打开原站的请求演示，沿时间线找到 DNS 查询、TCP 建连与 HTTP 请求，并在纸上画箭头。
先预测
如果还不知道域名对应的地址，HTTP 请求能直接送到正确服务器吗？写下你预计的先后顺序。
讲清楚
用“查地址—建连接—提请求”解释这次演示。再说明：这是一条教学路径，不代表所有缓存与协议场景都相同。

02 / ELECTRONICS★ 入门
电压 V→电流 I↔电阻 R

Electronics 101

从一个闭合回路开始

灯为什么亮？从开路、闭路和导体出发，把电压、电流、电阻与看得见的电路现象连起来。

探索内容：电路类型 · 串并联电池 · AC/DC · 面包板 · 万用表 · Kirchhoff 定律

先会什么 认识电池与灯；愿意先画出一条完整回路。

动手做
先在原站比较开路与闭路，再观察串联、并联的连接方式。画出电流能够经过的路径。
先预测
在电压保持不变的理想简单电路中，把电阻增大，电流会变大还是变小？用 V、I、R 说出依据。
讲清楚
为什么“接了两根线”不一定构成回路？解释电压与电流的区别，再指出串联与并联的一处不同。

实物边界：只做成人确认的低压电池实验，不碰市电；不能把万用表电流档直接跨接电池两端。

03 / OUTDOORS★ 入门 · 成人陪同
停下→评估→求助

Backcountry 101

出发之前，先学会安全

19 节户外主题涉及火、水、绳结、天幕、地图指南针、迷路、装备与蘑菇。先学风险判断，不把网页当生存许可证。

建议先看：迷路应对 · 装备清单 · 地图与指南针导航

先会什么 与成人约定出行计划和求助方式；知道不确定时要停下来求助。

动手做
与成人读完迷路和装备相关内容，做一次室内情景演练：天快黑、手机信号差，你会留下哪些信息、优先检查哪些装备？
先预测
“沿看起来像路的方向继续走”一定更容易获救吗？先写风险，再与课程中的迷路应对原则对照。
讲清楚
向同行人说明出发前的路线、折返点与失联约定；解释为什么净水过滤与安全饮用不能画等号。

安全红线：这不是可食用鉴定指南；不食用任何未可靠鉴定的植物或蘑菇。过滤不等于消毒，饮水处理需合适的消毒步骤。儿童不得独自生火或用刀；遵守当地禁火规定。实地活动须成人带领，网页不能替代专业指导。

04 / ARDUINO★ 入门
输入→程序→输出

Learn Arduino

认识一块开发板

围绕 Uno / ATmega328P 的入门 3D 课程。先在模型中认清板子与连接，再把“输入—处理—输出”说成一个完整故事。

探索内容：Uno 开发板 · ATmega328P · 3D 入门交互

先会什么 理解闭合回路；知道程序可以控制硬件。

动手做
在原站观察 3D 开发板，对照界面标注，找一找主控芯片、USB 接口与引脚区域，画一张位置草图。
先预测
一块外观相似的开发板，能直接照搬相同接线吗？先列出你认为要核对的型号、电压与引脚信息。
讲清楚
用一个按钮控制灯的例子说明：什么是输入，程序要做什么判断，什么是输出？这是导学设问，不代表原站有该实作关卡。

实物边界：这里的对象是 Uno / ATmega328P，不代表所有 Arduino 兼容板。先核对板型和引脚图，断电接线，勿短接电源。

05 / ESP32★★ 进阶
传感器→ESP32→执行器

Learn ESP32

让电路感知，再作出响应

20 节课程串起 GPIO、无线连接与常见外设。从灯和传感器出发，理解开发板如何把程序变成真实世界的变化。

探索内容：GPIO · WiFi · Bluetooth · LED · 传感器 · 电机 · 水泵

先会什么 电源、地与信号的区别；能读简单程序，并理解输入与输出。

动手做
先看原站 GPIO 与 LED 相关内容，画出“信号从哪个引脚出去”的路径，再找一个传感器主题，补画输入方向。
先预测
如果传感器超过阈值就启动水泵，读数在阈值附近来回波动时会怎样？先画预测曲线，再思考是否需要不同的启停阈值。
讲清楚
区分信号线与供电线：为什么 GPIO 能发送控制信号，却不应直接给电机或水泵供电？上面的水泵策略是延伸设问，不是原站功能承诺。

接线前必读：ESP32 GPIO 是 3.3V 逻辑，不能直接接 5V 信号；实际板型与引脚分配可能不同，须查对应引脚图。电机、水泵需合适的驱动与独立供电设计，由成人核对；勿用 GPIO 直接驱动负载。

06 / SYSTEM DESIGN★★★ 挑战
请求→服务→数据库

Designed to Scale

如果一万人同时点开呢？

从请求经过浏览器、DNS、连接、服务器与数据库开始，再进入扩展、存储和安全。重点不是记术语，而是解释选择的代价。

探索内容：请求链路 · 系统扩展 · 数据存储 · 安全

先会什么 先理解网络请求；知道服务器处理请求、数据库保存和读取数据。

动手做
在原站跟一次请求的完整旅程，画出浏览器到数据库的链路。在你觉得可能“排队”的位置标一个问号。
先预测
服务器增加一倍，响应速度就一定翻倍吗？假设瓶颈在数据库，先写下你预计不会被解决的问题。
讲清楚
选扩展、存储或安全中的一个设计，说出它解决了什么问题、引入什么成本，以及什么时候不值得用。
